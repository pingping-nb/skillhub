# SkillHub Helm Chart

企業級 AI 技能中心私有化部署方案，基於 Kubernetes 和 Helm。

## 特性

- **微服務架構**：Server（Spring Boot）、Web（Nginx）、Scanner 分離部署
- **高可用**：支援 HPA 自動擴縮容、PDB Pod 中斷預算
- **資料層**：使用 Bitnami PostgreSQL/Redis，支援主從複製、哨兵模式
- **安全**：TLS 證書管理、Secret 密碼保護；Bitnami 資料元件預設提供 NetworkPolicy
- **可觀測性**：內建 Prometheus metrics exporter

## 快速開始

### 前置要求

- Kubernetes 1.24+
- Helm 3.8+
- kubectl configured

### 安裝

先建立受保護的 `values-production.yaml`。以下值必須替換為實際隨機強密碼：

```yaml
secrets:
  allowAutoGenerated: false
  bootstrapAdminPassword: "<固定管理員密碼>"
  downloadAnonCookieSecret: "<至少32字元的固定隨機值>"

postgresql:
  auth:
    postgresPassword: "<固定PostgreSQL管理員密碼>"
    password: "<固定skillhub使用者密碼>"

redis:
  auth:
    password: "<固定Redis密碼>"
```

```bash
helm dependency build ./charts/skillhub
kubectl create namespace skillhub

helm -n skillhub upgrade -i skillhub ./charts/skillhub \
  -f values-production.yaml \
  --set publicBaseUrl=https://skills.example.com
```

未顯式設定 `deviceAuthVerificationUri` 時，Chart 使用
`<publicBaseUrl>/cli/auth`。所有 values 會先經過 `values.schema.json` 和跨欄位校驗，
無效的元件、Ingress、HPA 與儲存組合會在安裝前失敗。

> **Ingress values 遷移：** 當前版本只支援結構化的 `ingress.hosts[]` 和
> `ingress.tls[]`。舊的 `ingress.host`、`ingress.tls.enabled` 與
> `ingress.tls.secretName` 不再接受，升級前必須改成本文 Ingress 示例中的陣列結構。

合併或發布前，可在一個空的測試 Kubernetes 叢集中執行可重複的安裝/升級 smoke：

```bash
for scenario in default sentinel s3 ingress-tls; do
  HELM_SMOKE_SCENARIO="$scenario" \
    bash charts/skillhub/tests/install-upgrade-smoke.sh
done
```

指令碼驗證 `install -> Ready -> HTTP health -> upgrade -> Ready`，並確認 Secret 資料、
PVC UID 與繫結 PV 在升級前後保持不變。四個場景分別覆蓋預設依賴、Redis
Sentinel、實際 MinIO S3 連線，以及由 Kubernetes API 接受的 TLS Ingress 路由。
預設清理自己建立的 namespace；設定 `KEEP_HELM_SMOKE=true` 可保留現場用於排查。

### 使用 existingSecret

透過 `existingSecret` 引用已存在的 Secret 物件，避免在 values 中明文寫入密碼。
內建 PostgreSQL/Redis 使用各自的 Bitnami Secret，不需要複製到該 Secret。

| Key | 必填 | 說明 |
|-----|------|------|
| `spring-datasource-password` | 使用外部 PostgreSQL 時 | 資料庫密碼 |
| `redis-password` | 使用外部 Redis 時 | Redis 密碼 |
| `redis-sentinel-password` | 使用外部 Sentinel 時 | Redis Sentinel 密碼 |
| `bootstrap-admin-password` | 是 | 初始管理員密碼 |
| `skillhub-download-anon-cookie-secret` | 是 | 至少 32 字元的匿名下載 Cookie 簽名金鑰 |
| `oauth2-github-client-id` | 否 | GitHub OAuth2 Client ID |
| `oauth2-github-client-secret` | 否 | GitHub OAuth2 Client Secret |
| `skill-scanner-llm-api-key` | 否 | Scanner LLM API Key |
| `skill-scanner-llm-base-url` | 否 | Scanner 自定義 LLM API 地址 |
| `skill-scanner-llm-model` | 否 | Scanner LLM 模型名稱 |
| `skillhub-storage-s3-access-key` | 否 | S3 Access Key |
| `skillhub-storage-s3-secret-key` | 否 | S3 Secret Key |

```bash
helm -n skillhub upgrade -i skillhub ./charts/skillhub \
  -f values-production.yaml \
  --set existingSecret=my-custom-secret
```

### GitOps 穩定 Secret

Argo CD 等 GitOps 工具使用離線 `helm template`，無法透過 Helm `lookup` 讀取叢集
中已有的 Secret。Bitnami 子 Chart 和父 Chart 的空密碼會在每次渲染時重新隨機
生成。Chart 預設禁止自動生成並要求提供固定值：

```yaml
secrets:
  allowAutoGenerated: false
  bootstrapAdminPassword: "<固定管理員密碼>"
  downloadAnonCookieSecret: "<至少32字元的固定隨機值>"

postgresql:
  auth:
    postgresPassword: "<固定PostgreSQL管理員密碼>"
    password: "<固定skillhub使用者密碼>"
    # replication 架構還必須配置 replicationPassword

redis:
  auth:
    password: "<固定Redis密碼>"
```

也可以為三個元件分別配置 `existingSecret`。`allowAutoGenerated=false` 不會生成
可預測密碼，而是在任何隨機密碼缺失時終止渲染並指出具體配置項。敏感值應放在
受保護的 values、External Secrets、Sealed Secrets 或金鑰注入外掛中。

內建 PostgreSQL、Redis、Sentinel 及 metrics exporter 映象預設使用不可變的
多架構 manifest digest，避免 Bitnami 子 Chart 的 `latest` 預設值造成不可復現的
安裝和回滾，同時保留 amd64/arm64 支援。覆蓋私有映象倉庫或 tag 時，必須同時把
對應的 `image.digest` 設為空，或改成私有倉庫中該映象的真實 digest；digest
非空時會優先於 tag。

| `web.replicaCount` | Web 副本數 | `1` |
| `scanner.replicaCount` | Scanner 副本數 | `1` |

```bash
# 差異化副本配置
helm -n skillhub upgrade -i skillhub ./charts/skillhub \

  --set server.storage.accessMode=ReadWriteMany \
```

### 私有映象倉庫

使用私有倉庫時，需要分別覆蓋 SkillHub 映象、依賴等待映象和 Bitnami 子 Chart
映象。以下示例中的資料庫映象標籤均為明確版本，不使用 `latest`：

```yaml
global:
  imagePullSecrets:
    - private-registry
  security:
    allowInsecureImages: true

images:
  registry: registry.example.com/library
  tag: v0.2.14
  pullPolicy: IfNotPresent

server:
  dependencyWait:
    image:
      registry: registry.example.com
      repository: library/busybox
      tag: "1.37"
      pullPolicy: IfNotPresent
  imagePullSecrets:
    - name: private-registry

web:
  imagePullSecrets:
    - name: private-registry

scanner:
  imagePullSecrets:
    - name: private-registry

postgresql:
  image:
    registry: registry.example.com
    repository: library/postgresql
    tag: 18.4.0
    digest: ""
  metrics:
    image:
      registry: registry.example.com
      repository: library/postgres-exporter
      tag: 0.20.1
      digest: ""

redis:
  image:
    registry: registry.example.com
    repository: library/redis
    tag: 8.8.0
    digest: ""
  sentinel:
    image:
      registry: registry.example.com
      repository: library/redis-sentinel
      tag: 8.8.0
      digest: ""
  metrics:
    image:
      registry: registry.example.com
      repository: library/redis-exporter
      tag: 1.86.0
      digest: ""
```

`global.security.allowInsecureImages` 是 Bitnami 對自定義映象倉庫和映象名稱的校驗
開關，並不表示使用不安全的 HTTP 倉庫。先在目標 namespace 建立拉取憑據：

```bash
kubectl create secret docker-registry private-registry \
  -n skillhub \
  --docker-server=registry.example.com \
  --docker-username='<使用者名稱>' \
  --docker-password='<密碼>'
```

| 引數 | 描述 | 預設值 |
|------|------|--------|
| `postgresql.enabled` | 啟用內建 PostgreSQL | `true` |
| `postgresql.architecture` | 架構模式 | `standalone` |
| `redis.enabled` | 啟用內建 Redis | `true` |
| `redis.architecture` | 架構模式 | `standalone` |

#### 資料庫架構支援邊界

以下內建資料庫目標架構已完成獨立 namespace 的全新安裝和執行時驗證：

| 資料元件 | 已驗證架構 | 執行時驗證 |
|----------|------------|------------|
| PostgreSQL | standalone | Server 連線、Flyway 和應用啟動 |
| PostgreSQL | replication | 1 Primary + 2 Read Replicas，兩個副本均處於 recovery，流複製狀態為 `streaming` |
| Redis | standalone | Server 讀寫和應用啟動 |
| Redis | replication | 1 Master + 2 Replicas，角色和資料複製正常 |
| Redis | replication + Sentinel | 3 個 Sentinel 節點 master 檢視一致，Server 可透過 Sentinel 讀寫 |

上述支援表示 Chart 能夠全新部署目標架構，併為 SkillHub 配置正確的寫節點或
Sentinel 地址。Chart **不負責資料庫架構切換時的資料遷移**，也不承諾僅修改
`architecture` 或 `sentinel.enabled` 就能保留已有資料。已有資料的 PostgreSQL
standalone → replication、Redis standalone/replication → Sentinel 等切換，必須由
運維人員在 Chart 之外完成備份、恢復、PVC 複用或其他遷移方案。

外部 Redis Cluster 由雲服務或運維繫統提供，Chart 只負責注入連線配置，不建立
Cluster，也不將其計入上述內建架構執行時驗證範圍。應用側應另行驗證 Spring
Data、Spring Session 與 Redisson Stream 鏈路。

### Redis Sentinel

內建 Sentinel 使用 Bitnami Redis 的同一份密碼同時保護 Redis 資料節點和
Sentinel。節點地址由副本數自動生成，不需要手動配置。由於 Bitnami Sentinel
上報的 Pod 地址可能與客戶端連線的 Headless Service FQDN 不同，Chart 僅在該
內建模式下關閉 Redisson 的 Sentinel 地址一致性檢查：

```bash
helm -n skillhub upgrade -i skillhub ./charts/skillhub \
  -f values-production.yaml \
  --set redis.architecture=replication \
  --set redis.sentinel.enabled=true
```

外部 Sentinel 必須提供至少一個 `host:port` 節點。Redis 資料密碼和 Sentinel
密碼可以不同；使用 `existingSecret` 時分別對應 `redis-password` 和
`redis-sentinel-password`。外部 Sentinel 預設保留 Redisson 地址一致性檢查；
只有已確認服務發現會改寫節點地址時，才透過 `server.extraEnv` 顯式設定
`SKILLHUB_REDIS_SENTINEL_CHECK_SENTINELS_LIST=false`：

```bash
helm -n skillhub upgrade -i skillhub ./charts/skillhub \
  -f values-production.yaml \
  --set redis.enabled=false \
  --set externalRedis.password=redis-password \
  --set externalRedis.sentinel.enabled=true \
  --set externalRedis.sentinel.password=sentinel-password \
  --set-json 'externalRedis.sentinel.nodes=["sentinel-0.example.com:26379","sentinel-1.example.com:26379"]'
```

確需關閉檢查時，在 values 檔案中顯式記錄該相容例外：

```yaml
server:
  extraEnv:
    - name: SKILLHUB_REDIS_SENTINEL_CHECK_SENTINELS_LIST
      value: "false"
```

### 外部 Redis Cluster

Chart 不建立內建 Redis Cluster。生產環境的 Cluster 由雲 Redis 或獨立運維繫統
提供，SkillHub 透過標準 Spring Boot 配置連線。至少配置一個 seed 節點，且
Cluster 通告的所有節點地址都必須能從 Server Pod 訪問：

```yaml
redis:
  enabled: false

externalRedis:
  username: skillhub
  tls:
    enabled: true
  connectTimeout: 5s
  timeout: 3s
  clientName: skillhub-server
  cluster:
    enabled: true
    nodes:
      - redis-0.example.com:6379
      - redis-1.example.com:6379
      - redis-2.example.com:6379
    maxRedirects: 5
```

Redis Cluster 只支援資料庫 `0`。`maxRedirects` 交給 Spring Data/Lettuce 處理；
Redisson 使用同一節點、ACL、TLS 與超時配置並自行處理 Cluster 路由。密碼建議
透過 `existingSecret` 的 `redis-password` 提供：

```bash
helm -n skillhub upgrade -i skillhub ./charts/skillhub \
  -f values-production.yaml \
  --set redis.enabled=false \
  --set existingSecret=skillhub-production-secret \
  --set externalRedis.cluster.enabled=true \
  --set-json 'externalRedis.cluster.nodes=["redis-0.example.com:6379","redis-1.example.com:6379","redis-2.example.com:6379"]'
```

`externalRedis.sentinel.enabled` 與 `externalRedis.cluster.enabled` 互斥；內建
`redis.enabled=true` 時也不能啟用外部 Cluster。

### 儲存配置

| 引數 | 描述 | 預設值 |
|------|------|--------|
| `server.storage.accessMode` | 留空時單副本使用 ReadWriteOnce；多副本必須顯式使用 ReadWriteMany | `""` |
| `server.storage.size` | PVC 大小 | `10Gi` |
| `server.storage.storageClassName` | StorageClass | `""` |
| `server.podSecurityContext.fsGroup` | Server 本地儲存的可寫組 ID，應與映象內 app 使用者組一致 | `101` |
| `server.podSecurityContext.fsGroupChangePolicy` | kubelet 調整 PVC 組許可權的策略 | `OnRootMismatch` |

本地 PVC 會覆蓋映象內預先設定的目錄所有者。Chart 預設透過 Pod `fsGroup=101`
使 Server 的非 root `app` 使用者可以建立和更新技能檔案。使用自定義 Server 映象且其
執行組 ID 不同時，必須同步覆蓋 `server.podSecurityContext.fsGroup`。

使用本地 `ReadWriteOnce` PVC 時，Server Deployment 自動採用 `Recreate`，避免
滾動升級期間新舊 Pod 同時掛載非共享卷而觸發 Multi-Attach。單副本升級會有短暫
停機；使用支援 RWX 的 `ReadWriteMany` 儲存或啟用 S3 時，Chart 保留
`RollingUpdate`。

```bash
# 預設使用本地 PVC
helm -n skillhub upgrade -i skillhub ./charts/skillhub \
  -f values-production.yaml
```

### S3 物件儲存

`s3.enabled=true` 時，不建立 PVC，應用使用 S3 作為儲存後端。

| 引數 | 描述 | 預設值 |
|------|------|--------|
| `s3.enabled` | 啟用 S3 | `false` |
| `s3.bucket` | Bucket 名稱 | `skillhub-storage` |
| `s3.endpoint` | S3 端點，非空時必須是絕對 HTTP(S) URL | `""` |
| `s3.publicEndpoint` | S3 公網訪問端點，非空時必須是絕對 HTTP(S) URL | `""` |
| `s3.region` | 區域 | `us-east-1` |
| `s3.forcePathStyle` | 強制 path-style 訪問 | `true` |
| `s3.disableChunkedEncoding` | 禁用 aws-chunked 編碼 | `false` |
| `s3.autoCreateBucket` | 自動建立 Bucket | `false` |
| `s3.accessKey` | Access Key | `""` |
| `s3.secretKey` | Secret Key | `""` |

```bash
helm -n skillhub upgrade -i skillhub ./charts/skillhub \
  -f values-production.yaml \
  --set s3.enabled=true \
  --set s3.bucket=your-bucket \
  --set s3.endpoint=https://s3.amazonaws.com \
  --set s3.region=us-east-1 \
  --set s3.accessKey=your-access-key \
  --set s3.secretKey=your-secret-key
```

### Ingress + TLS

```bash
helm -n skillhub upgrade -i skillhub ./charts/skillhub \
  -f values-production.yaml \
  --set ingress.enabled=true \
  --set-json 'ingress.hosts=[{"host":"skills.example.com","paths":[{"path":"/","pathType":"Prefix"}]}]' \
  --set-json 'ingress.tls=[{"hosts":["skills.example.com"],"secretName":"skills-tls"}]' \
  --set publicBaseUrl=https://skills.example.com \
  --set ingress.certManager.enabled=true
```

配置非空 `ingress.tls` 或啟用 `ingress.certManager` 時，Chart 會自動將 Session Cookie
標記為 Secure。Ingress 要求 Server 和 Web Service 均保持啟用。

`ingress.className` 和舊式 `kubernetes.io/ingress.class` annotation 均受支援，
可以任選其一，也可以同時輸出。僅使用舊式 annotation 時將 `className` 留空：

```yaml
ingress:
  enabled: true
  className: ""
  annotations:
    kubernetes.io/ingress.class: alb
    alb.ingress.kubernetes.io/listen-ports: '[{"HTTPS":6443}]'
```

`hosts` 是至少包含一個條目的物件陣列。Chart 自動將 `/api`、`/oauth2`、
`/login/oauth2` 和 `/.well-known` 直接轉發給 Server，確保 TLS 終止後的 OAuth
回撥協議保持正確；`hosts[].paths` 中的其他路徑轉發給 Web，因此上述四個字首
均為保留路徑。`tls` 同樣是陣列，可為不同證書分別配置域名；TLS 域名會寫入
cert-manager Certificate SAN：

```yaml
ingress:
  hosts:
    - host: skills.example.com
      paths:
        - path: /
          pathType: Prefix
    - host: skills.internal.example.com
      paths:
        - path: /
          pathType: Prefix
  tls:
    - hosts:
        - skills.example.com
        - skills.internal.example.com
      secretName: skills-tls
```

### 自動擴縮容

```bash
helm -n skillhub upgrade -i skillhub ./charts/skillhub \
  -f values-production.yaml \
  --set server.autoscaling.enabled=true \
  --set server.autoscaling.minReplicas=2 \
  --set server.autoscaling.maxReplicas=10 \
  --set server.storage.accessMode=ReadWriteMany
```

每個 HPA 至少需要一個非零 CPU 或記憶體利用率目標。本地儲存的 Server HPA 同樣
要求 RWX；也可以啟用 S3 來避免共享 PVC。

## 發布

`.github/workflows/publish-chart.yml` 在 GitHub Release 發布後或手動
`workflow_dispatch` 時執行。Release tag 必須使用 `vX.Y.Z`、`chart-vX.Y.Z` 或
`helm-vX.Y.Z`；手動執行時顯式輸入 `X.Y.Z`。工作流按該版本打包 Chart，並推送到
`oci://ghcr.io/iflytek/charts`，同時保留構建 artifact。

## 解除安裝

```bash
helm -n skillhub uninstall skillhub
```

Server 資料 PVC 帶有 `helm.sh/resource-policy: keep`，解除安裝 release 後仍會保留，
需要確認資料不再使用後手動刪除。

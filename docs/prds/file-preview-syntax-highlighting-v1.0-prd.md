# 檔案預覽語法高亮 - 產品需求檔案 (PRD)

## 需求描述

### 背景
- **業務問題**：當前檔案預覽功能僅對 Markdown 檔案提供語法高亮渲染，其他程式碼檔案（Python、Shell、Java、TypeScript 等）只顯示純文字，使用者體驗不佳，無法快速理解程式碼結構。
- **目標使用者**：技能開發者、稽核人員、技能使用者
- **價值主張**：提供與 Markdown 程式碼塊一致的高質量語法高亮，提升程式碼可讀性，加速程式碼審查和理解效率。

### 功能概述
- **核心功能**：
  1. 為常見程式語言（Python, Shell, Java, JS/TS, Go, Rust, C/C++, Ruby, PHP）提供語法高亮
  2. 為配置檔案（JSON, YAML, TOML, XML）提供語法高亮
  3. 複用現有的 rehype-highlight（基於 highlight.js）渲染引擎
  4. 保持與 Markdown 程式碼塊一致的視覺樣式
  5. 支援 dark/light 主題自動切換

- **功能邊界**：
  - **包含**：常見程式語言和配置檔案的語法高亮、錯誤降級處理、效能最佳化
  - **不包含**：行號顯示、程式碼摺疊、語法錯誤檢測、自定義主題配置

- **使用者場景**：
  1. 技能稽核人員檢視提交的 Python 指令碼，快速識別程式碼邏輯
  2. 開發者預覽技能包中的配置檔案（如 skill.yaml），確認引數配置
  3. 使用者瀏覽技能原始碼，瞭解實現細節

### 詳細需求
- **輸入/輸出**：
  - 輸入：檔案路徑、檔案內容（InputStream）、副檔名
  - 輸出：帶語法高亮的 HTML（透過 highlight.js 渲染）

- **使用者互動**：
  1. 使用者點選檔案樹中的程式碼檔案節點
  2. 前端顯示 loading 狀態
  3. 後端返回檔案內容和後設資料（大小、型別）
  4. 前端根據檔案大小和型別決定渲染策略：
     - ≤ 500KB：語法高亮渲染
     - 500KB < size ≤ 1MB：純文字渲染（無高亮）
     - > 1MB：僅顯示下載按鈕

- **資料要求**：
  - 檔案大小：透過 `SkillFile.fileSize` 欄位獲取
  - 檔案型別：透過副檔名推斷（`.py` → Python）
  - 語言對映：使用 `file-type-utils.ts` 中的對映表

- **邊界情況**：
  1. **無法識別的語言**：顯示純文字（無高亮），不報錯
  2. **語法高亮失敗**：降級到純文字顯示，記錄錯誤日誌
  3. **記憶體不足**：降級到純文字顯示，顯示提示資訊
  4. **大檔案（> 500KB）**：跳過語法高亮，直接顯示純文字
  5. **超大檔案（> 1MB）**：不預覽，僅提供下載

## 設計決策

### 技術方案
- **架構選擇**：複用現有的 rehype-highlight（基於 highlight.js）
  - **理由**：
    1. 零額外依賴，不增加包體積
    2. 樣式與 Markdown 程式碼塊完全一致
    3. 已有的語言支援（190+ 種語言）
    4. 維護成本低

- **關鍵元件**：
  1. **CodeRenderer 元件**（新增）：
     - 位置：`web/src/features/skill/code-renderer.tsx`
     - 職責：接收程式碼字串和語言型別，呼叫 highlight.js 渲染
     - 依賴：`highlight.js/lib/core` + 按需匯入的語言包

  2. **file-type-utils.ts**（擴充套件）：
     - 新增 `getLanguageForHighlight(extension: string): string | null` 函式
     - 對映副檔名到 highlight.js 語言識別符號

  3. **file-preview-dialog.tsx**（修改）：
     - 根據檔案大小和型別選擇渲染器：
       - Markdown → `MarkdownRenderer`
       - 程式碼檔案（≤ 500KB）→ `CodeRenderer`
       - 程式碼檔案（> 500KB）→ 純文字 `<pre><code>`
       - 其他 → 下載提示

- **資料儲存**：
  - 無需新增資料庫欄位
  - 檔案內容從雲端儲存（ObjectStorageService）讀取
  - 檔案大小已儲存在 `SkillFile.fileSize` 欄位

- **介面設計**：
  - 複用現有 API：`GET /api/v1/reviews/{id}/file?path={filePath}`
  - 響應格式：`InputStream`（保持不變）
  - 前端根據 `Content-Length` 響應頭判斷檔案大小

### 約束條件
- **效能要求**：
  - 語法高亮渲染時間：< 500ms（對於 500KB 檔案）
  - 首次載入時間：< 1s（包括網路請求）
  - 記憶體佔用：單個檔案渲染 < 50MB

- **相容性**：
  - 瀏覽器：Chrome 90+, Firefox 88+, Safari 14+, Edge 90+
  - 移動端：支援響應式佈局，但不最佳化觸控互動

- **安全性**：
  - 使用 `dangerouslySetInnerHTML` 時，確保 highlight.js 輸出已轉義
  - 防止 XSS 攻擊：不允許使用者自定義語法高亮規則
  - 檔案路徑驗證：複用現有的路徑遍歷防護（禁止 `..` 和絕對路徑）

- **可擴充套件性**：
  - 語言支援：透過按需匯入語言包擴充套件，不影響初始包體積
  - 主題支援：預留主題切換介面，當前僅支援跟隨系統主題

### 風險評估
- **技術風險**：
  - **風險**：大檔案語法高亮導致瀏覽器卡頓
  - **機率**：中
  - **影響**：高
  - **緩解措施**：
    1. 設定 500KB 閾值，超過則不高亮
    2. 增加 loading 狀態提示使用者
    3. 提供"取消載入"按鈕（後續最佳化）

- **依賴風險**：
  - **風險**：highlight.js 無法識別某些語言
  - **機率**：低
  - **影響**：低
  - **緩解措施**：降級到純文字顯示，不影響核心功能

- **進度風險**：
  - **風險**：後端快取和限流實現延期
  - **機率**：中
  - **影響**：中
  - **緩解措施**：
    1. 前端功能可獨立上線
    2. 後端最佳化作為獨立任務，分階段實施

## 附錄：後端最佳化方案（後續實施）

以下最佳化方案已記錄在檔案中，但不在本次實施範圍內，將作為獨立任務後續統一實現。

### 1. 後端快取策略
- **目標**：減少雲端儲存讀取次數，降低響應時間
- **方案**：
  - 使用 Redis 快取檔案內容
  - 快取鍵：`file:content:{storageKey}`
  - TTL：1 小時
  - 快取策略：LRU（最近最少使用）
- **預期效果**：
  - 快取命中率 > 60%
  - 響應時間降低 50%

### 2. 限流策略
- **目標**：防止檔案預覽 API 被濫用，保護後端服務
- **方案**：
  - 使用 `@RateLimit` 註解
  - 配置：
    ```java
    @RateLimit(
        category = "file-preview",
        authenticated = 60,    // 認證使用者：每分鐘 60 次
        anonymous = 20,        // 匿名使用者：每分鐘 20 次
        windowSeconds = 60
    )
    ```
  - 限流粒度：按使用者 ID（認證使用者）或 IP（匿名使用者）
  - 超出限流響應：返回 429 狀態碼 + `{"code": 429, "message": "error.rateLimit.exceeded"}`
- **預期效果**：
  - 防止單使用者/IP 過度請求
  - 保護雲端儲存 API 配額

### 3. 監控指標
- **目標**：實時監控檔案預覽功能的健康狀況
- **指標**：
  - 檔案預覽 API 響應時間（P50, P95, P99）
  - 檔案預覽 API 錯誤率
  - 快取命中率
  - 限流觸發次數
  - 雲端儲存 API 呼叫次數
- **告警規則**：
  - P95 響應時間 > 2s：警告
  - 錯誤率 > 5%：嚴重
  - 快取命中率 < 40%：警告

# 技能詳情與稽核頁檔案瀏覽側邊欄 - 產品需求檔案 (PRD)

## 需求說明

### 背景
- 當前技能詳情頁 `space/global/skill-writer` 與稽核詳情區塊都提供“概覽 / 檔案 / 版本”三個 Tab，但檔案區域僅展示平鋪檔案列表，無法在頁面內瀏覽目錄層級或直接檢視檔案內容。
- 技能詳情頁已經具備按路徑讀取單個檔案內容的能力，可用於 README 載入；稽核詳情頁目前僅返回 `files`、`documentationPath`、`documentationContent`，還不具備按任意檔案路徑讀取正文的能力。
- 使用者需要在不下載整個 zip 包的前提下，快速檢視 skill 包含的目錄結構與具體檔案內容，提升詳情瀏覽和稽核判斷效率。

### 業務問題
- 平鋪檔案列表無法反映目錄層級，使用者難以理解 skill 包結構。
- 稽核人員在稽核頁中無法點開任意檔案驗證實現內容，只能依賴 README 或下載壓縮包離線檢視。
- 現有三個 Tab 的主體內容已經承擔不同職責，若繼續把檔案瀏覽塞入當前“檔案”Tab，會使“概覽”與“版本”場景下的跨檔案檢視成本偏高。

### 目標使用者
- 瀏覽技能詳情的普通使用者
- 管理技能的作者 / 名稱空間成員
- 在稽核中心檢視技能內容的稽核人員與管理員

### 價值主張
- 用統一的側邊檔案瀏覽體驗取代當前平鋪檔案列表，降低理解 skill 包結構的成本。
- 在技能詳情頁和稽核頁提供一致的檔案預覽能力，減少下載操作和上下文切換。
- 保持現有三個 Tab 的主語義不變，同時讓使用者在任意 Tab 下都能快速檢視檔案內容。

## 功能概述

### 核心功能
1. 在技能詳情頁與稽核詳情頁中新增常駐檔案瀏覽側邊欄。
2. 將現有平鋪 `files` 列表重構為目錄樹，支援資料夾展開 / 合併。
3. 點選檔案節點後，透過彈窗預覽檔案內容。
4. 支援 Markdown 檔案渲染、常見文字檔案原始碼預覽，以及大檔案 / 不支援檔案型別的不可預覽提示。
5. 對不可預覽檔案提供下載入口。
6. 桌面端使用右側側邊欄佈局，移動端將檔案瀏覽區域下沉到主內容區域下方。

### 本次範圍
- 技能詳情頁：三個 Tab 下都顯示同一份基於當前主版本的檔案瀏覽側邊欄。
- 稽核詳情頁：三個 Tab 下都顯示檔案瀏覽側邊欄，並支援點選任意檔案預覽。
- 檔案樹預設展開第一層目錄，其餘目錄按需展開。
- 側邊欄需要顯示檔案型別或檔案大小等輔助資訊。
- 點選檔案後使用彈窗預覽，不切換當前 Tab。

### 明確不包含
- 側邊欄內建檔名搜尋 / 路徑過濾。
- 技能詳情頁中獨立切換檔案瀏覽版本。
- 稽核頁中的版本維度切換瀏覽許可權設計與互動實現。
- 圖片、音影片、富二進位制檔案的內聯預覽。
- 超大檔案截斷預覽。

### 後續可擴充套件方向
- 按版本瀏覽檔案樹與檔案預覽，並結合許可權控制設計訪問策略。
- 側邊欄搜尋過濾、最近開啟檔案、選中檔案高亮等增強互動。
- 對 JSON / YAML / TS / JS 等文字檔案提供更完整的語法高亮能力。
- 超大文字檔案受控截斷預覽，基於服務端預覽介面返回結構化後設資料。

## 詳細需求

### 使用者互動流程

#### 技能詳情頁
1. 使用者進入技能詳情頁，預設看到“概覽 / 檔案 / 版本”三個 Tab。
2. 無論當前停留在哪個 Tab，頁面都顯示檔案瀏覽側邊欄。
3. 側邊欄展示基於當前主版本的目錄樹，第一層目錄預設展開。
4. 使用者點選資料夾節點，可展開或收起該目錄。
5. 使用者點選檔案節點，開啟檔案預覽彈窗。
6. 若檔案是 Markdown，則按檔案樣式渲染。
7. 若檔案是常見文字檔案，則按原始碼塊樣式顯示。
8. 若檔案為二進位制、型別不支援或檔案過大，則彈窗展示“不可預覽”提示，並提供檔案下載入口。

#### 稽核詳情頁
1. 稽核人員展開稽核詳情區塊。
2. 在“概覽 / 檔案 / 版本”任一 Tab 下，都能看到檔案瀏覽側邊欄。
3. 稽核人員點選任意檔案後，開啟與技能詳情頁一致的檔案預覽彈窗。
4. 若稽核頁現有介面無法提供目標檔案正文，則需透過新增或擴充套件介面補齊能力。

### 頁面佈局要求

#### 桌面端
- 主內容區域與檔案瀏覽側邊欄形成雙欄佈局。
- 三個 Tab 的主內容保持原有語義：
  - 概覽：README / 檔案主體。
  - 檔案：檔案樹本身可作為主內容補充或說明區域，但不再是唯一的檔案入口。
  - 版本：版本列表與生命週期資訊。
- 檔案預覽使用獨立彈窗，避免改變主內容佈局或跳轉當前 Tab。

#### 移動端
- 不保留強制雙欄。
- 檔案瀏覽區域下沉到主內容區域之後，仍在三個 Tab 下可見。
- 檔案預覽彈窗優先採用接近全屏的移動端彈層體驗。
- 需避免任何橫向滾動作為主要互動方式。

### 檔案樹行為
- 輸入資料來源為現有平鋪 `SkillFile[]` 列表，前端負責構建樹形節點。
- 節點型別分為目錄節點與檔案節點。
- 目錄節點支援展開 / 收起。
- 檔案節點支援點選開啟預覽彈窗。
- 側邊欄中顯示檔案型別或檔案大小資訊，幫助使用者判斷檔案性質。
- 第一層目錄預設展開；更深層目錄預設摺疊。

### 檔案預覽行為
- Markdown 檔案：複用現有 Markdown 渲染能力。
- 文字檔案：優先以原始碼 / 純文字方式渲染，保留可滾動閱讀體驗。
- 二進位制檔案：展示“當前檔案型別暫不支援預覽”。
- 超大檔案：展示“檔案過大，暫不支援預覽”，並給出下載入口。
- 所有不可預覽檔案都必須提供可觸達的下載能力。
- 預覽彈窗需要顯示當前檔案路徑，便於使用者確認檢視物件。

### 資料與介面需求

#### 技能詳情頁
- 繼續複用當前按路徑讀取檔案正文的能力。
- 需要將當前 README 專用的單檔案讀取能力抽象成“任意檔案讀取”查詢邏輯，供預覽彈窗複用。

#### 稽核詳情頁
- 需要補齊按路徑讀取任意檔案正文的能力。
- 可接受的實現方式：
  1. 新增稽核場景專用檔案讀取介面。
  2. 擴充套件當前 review detail 資料獲取鏈路，增加任意檔案按路徑讀取能力。
- 目標是讓稽核頁的檔案預覽能力與技能詳情頁對齊，而不是僅支援 README。

### 開源元件策略
- 實現前需優先評估成熟開源元件是否能滿足檔案樹或程式碼預覽需求。
- 評估前提：樣式必須能與當前 React + Tailwind + 現有 UI 體系自然融合。
- 若第三方元件在樣式一致性、包體積、移動端適配或維護成本上不滿足要求，則回退為輕量自研方案。
- 當前專案已具備 `react-markdown`、`rehype-highlight` 與現有 Dialog 基礎能力，應優先複用已有依賴，避免引入風格衝突較大的重型元件。

## 設計決策

### 互動決策
- 採用“常駐檔案導航 + 彈窗預覽”模式，而不是切換主內容 Tab 或在側邊欄內直接閱讀正文。
- 理由：
  - 保持現有三個 Tab 的語義穩定。
  - 允許使用者在“概覽”或“版本”上下文中快速檢視檔案。
  - 更適合移動端，將閱讀行為獨立到彈窗層處理。

### 響應式決策
- 桌面端為右側常駐側邊欄。
- 移動端為主內容下方檔案瀏覽區 + 接近全屏的預覽彈層。
- 需保證 320 / 375 / 414 / 768 / 1024 / 1440 等常見寬度下無異常橫向滾動。

### 樣式與可用性決策
- 延續當前頁面的資料密集型管理介面風格，不引入與現有設計系統衝突的第三方視覺語言。
- 檔案樹節點、彈窗關閉按鈕、下載按鈕需具備清晰 hover / focus 狀態。
- 互動動效應控制在 150-300ms 範圍內，並尊重 `prefers-reduced-motion`。
- 移動端點選目標需滿足最小可觸達尺寸。

## 技術約束

### 前端約束
- 必須相容現有技能詳情頁與稽核詳情頁結構，不破壞當前三個 Tab 的主內容與既有操作。
- 複用現有 Dialog、MarkdownRenderer、i18n、TanStack Query 模式。
- 檔案樹由前端從平鋪檔案列表構建，不要求後端返回巢狀目錄結構。
- 不允許因為引入新元件導致現有樣式體系明顯漂移。

### 後端約束
- 本期允許為稽核頁補充新介面或擴充套件現有返回結構，但應避免引入資料庫 schema 變化。
- 檔案讀取能力應限定在當前稽核上下文可訪問的 skill 版本上，不擴大許可權邊界。
- 對超大檔案 / 不支援預覽型別應能返回明確錯誤或元資訊，便於前端區分不可預覽原因。

### 效能約束
- 開啟檔案樹不應阻塞頁面初次渲染。
- 檔案預覽按需載入，不能一次性拉取所有檔案正文。
- 目錄樹展開 / 收起應保持即時響應，不因大規模重渲染造成明顯示卡頓。

### 安全約束
- 繼續沿用現有技能詳情頁和稽核頁的鑑權邊界。
- 稽核頁新增檔案正文讀取能力時，必須確保僅稽核相關角色可訪問對應資源。
- 不可透過構造任意路徑越權讀取 skill 包之外的內容。

### 國際化約束
- 中英文都需補充檔案瀏覽、預覽、不可預覽、大檔案提示、下載操作等文案。

## 風險評估

### 技術風險
1. 稽核頁缺少任意檔案正文讀取能力，若後端介面設計不清晰，可能導致前後端聯調返工。
2. 第三方檔案樹 / 程式碼檢視元件可能與現有 Tailwind 風格不匹配，帶來樣式整合成本。
3. 檔案型別判斷與大檔案判定策略若不統一，可能導致詳情頁與稽核頁行為不一致。

### 互動風險
1. 桌面端雙欄與移動端單欄切換如果佈局邊界控制不好，容易出現橫向滾動或內容擁擠。
2. 彈窗預覽若對長文書處理不當，可能造成滾動區域難用或閱讀效率差。

### 緩解措施
- 優先複用現有 Markdown、Dialog 與查詢模式，減少引入面。
- 將“按路徑讀取正文”的能力抽象為共享模型，詳情頁和稽核頁統一使用。
- 先定義統一的“可預覽 / 不可預覽 / 可下載”判定規則，再進入實現。
- 將第三方元件引入作為可選路徑，而非前置依賴。

## 驗收標準

### 功能驗收
- 技能詳情頁三個 Tab 下均能看到檔案瀏覽側邊欄。
- 稽核詳情頁三個 Tab 下均能看到檔案瀏覽側邊欄。
- 平鋪檔案列表能正確轉換為目錄樹，且支援資料夾展開 / 收起。
- 點選檔案節點後能開啟預覽彈窗。
- Markdown 檔案能正確渲染。
- 常見文字檔案能以原始碼 / 純文字形式展示。
- 二進位制檔案或超大檔案會顯示不可預覽提示。
- 不可預覽檔案提供下載入口。
- 稽核頁支援點選任意檔案並預覽，不侷限於 README。

### 質量驗收
- 桌面端採用右側側邊欄佈局，移動端檔案瀏覽區下沉到主內容下方。
- 頁面在常見斷點下無異常橫向滾動。
- 不影響現有“概覽 / 檔案 / 版本”Tab 的既有內容與操作。
- 新增文案完成中英文國際化覆蓋。

## 執行階段

### Phase 1: 共享模型與互動方案落地
- 明確檔案樹節點模型、可預覽型別規則、不可預覽提示規則。
- 評估是否存在可複用的開原始檔樹 / 文字預覽能力，並完成選型結論。

### Phase 2: 技能詳情頁整合
- 抽象任意檔案讀取查詢邏輯。
- 將技能詳情頁平鋪檔案列表升級為目錄樹側邊欄。
- 接入彈窗預覽與下載能力。

### Phase 3: 稽核頁能力補齊
- 為稽核頁補充任意檔案正文讀取介面或資料鏈路。
- 在稽核詳情區塊接入共享檔案樹與預覽彈窗。

### Phase 4: 迴歸與體驗完善
- 補充中英文文案。
- 驗證桌面端 / 移動端佈局、彈窗滾動、不可預覽場景。
- 補充迴歸測試，確保現有 Tab 內容和稽核流程不受影響。

## 非本期需求記錄
- 檔案瀏覽版本切換需要單獨設計許可權邊界、互動入口和不影響現有功能的約束，本期僅記錄，不實現。

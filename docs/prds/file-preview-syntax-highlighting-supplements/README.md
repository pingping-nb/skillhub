## 業務規則速查

| 規則 ID | 描述 | 優先順序 |
|---------|------|--------|
| BR-001 | 檔案大小 > 500KB → 純文字（無高亮） | Must |
| BR-002 | 檔案大小 > 1MB → 僅下載 | Must |
| BR-003 | 無法識別語言 → 純文字（不報錯） | Must |
| BR-004 | 渲染失敗 → 降級到純文字 | Must |
| BR-005 | 記憶體不足 → 降級到純文字 | Should |
| BR-006 | 主題跟隨系統 | Must |
| BR-007 | 樣式與 Markdown 一致 | Must |
| BR-008 | 複製功能保留 | Must |

## 檔案使用指南

### 開發階段
1. **開始開發前**：閱讀 PRD 和約束規範，理解功能邊界和業務規則
2. **編寫程式碼時**：參考影響分析，瞭解需要修改的檔案
3. **編寫測試時**：參考驗收用例和測試計劃，確保覆蓋所有場景
4. **程式碼審查時**：檢查是否滿足所有業務規則（BR-XXX）

### 測試階段
1. **單元測試**：按照測試計劃執行，確保覆蓋率 > 80%
2. **整合測試**：驗證所有驗收用例（AC-XXX）
3. **效能測試**：確保滿足效能約束（500KB < 500ms）
4. **安全測試**：驗證 XSS 防護（AC-S-XXX）

### 部署階段
1. **部署前**：檢查回滾計劃是否就緒
2. **部署後**：監控錯誤率和效能指標
3. **問題排查**：參考風險評估（R-XXX）定位問題

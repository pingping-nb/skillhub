## 5. 風險評估

| 風險 ID | 描述 | 機率 | 影響 | 緩解措施 |
|---------|------|------|------|---------|
| R-001 | 大檔案語法高亮導致瀏覽器卡頓 | 中 | 高 | 設定 500KB 閾值，超過則不高亮 |
| R-002 | highlight.js 包體積過大 | 低 | 中 | 按需匯入語言包，初始只載入核心 |
| R-003 | 語法高亮樣式與 Markdown 不一致 | 低 | 中 | 複用相同的 CSS 類名和樣式 |
| R-004 | 某些語言無法識別 | 低 | 低 | 降級到純文字顯示，不報錯 |
| R-005 | 渲染失敗導致頁面崩潰 | 低 | 高 | 使用 Error Boundary 捕獲錯誤 |
| R-006 | 主題切換時樣式閃爍 | 低 | 低 | 使用 CSS 變數，確保平滑過渡 |
| R-007 | 後端檔案讀取效能下降 | 中 | 中 | 後續實現快取和限流（不在本次範圍） |
| R-008 | XSS 安全風險 | 低 | 高 | 確保 highlight.js 輸出已轉義 |

### 風險詳細說明

#### R-001: 大檔案語法高亮導致瀏覽器卡頓
- **觸發條件**：使用者嘗試預覽 > 500KB 的程式碼檔案
- **影響範圍**：前端渲染效能，使用者體驗
- **緩解措施**：
  1. 設定 500KB 閾值，超過則顯示純文字
  2. 增加 loading 狀態提示使用者
  3. 提供"取消載入"按鈕（後續最佳化）
- **監控指標**：前端渲染時間（透過 RUM）

#### R-005: 渲染失敗導致頁面崩潰
- **觸發條件**：highlight.js 渲染異常、記憶體不足
- **影響範圍**：檔案預覽功能不可用
- **緩解措施**：
  1. 使用 React Error Boundary 捕獲渲染錯誤
  2. 降級到純文字顯示
  3. 記錄錯誤日誌，便於排查
- **監控指標**：錯誤率（透過前端錯誤監控）

#### R-007: 後端檔案讀取效能下降
- **觸發條件**：大量使用者同時預覽檔案
- **影響範圍**：後端 API 響應時間增加，雲端儲存 API 配額消耗
- **緩解措施**：
  1. 後續實現 Redis 快取（快取命中率 > 60%）
  2. 後續實現限流（認證使用者 60 次/分鐘，匿名 20 次/分鐘）
  3. 監控雲端儲存 API 呼叫次數
- **監控指標**：API 響應時間、快取命中率、限流觸發次數

#### R-008: XSS 安全風險
- **觸發條件**：惡意使用者上傳包含 XSS 程式碼的檔案
- **影響範圍**：安全漏洞，可能導致使用者資訊洩露
- **緩解措施**：
  1. 確保 highlight.js 輸出已轉義（highlight.js 預設轉義）
  2. 程式碼審查確認 `dangerouslySetInnerHTML` 使用安全
  3. 不允許使用者自定義語法高亮規則
- **監控指標**：安全審查透過

## 8. 回滾計劃

### 回滾觸發條件
- 前端渲染錯誤率 > 5%
- 使用者投訴語法高亮功能異常 > 10 次/天
- 效能指標嚴重下降（P95 響應時間 > 3s）

### 回滾步驟
1. **前端回滾**：
   - 回滾到上一個穩定版本（git revert）
   - 重新構建和部署前端
   - 驗證檔案預覽功能恢復正常（顯示純文字）
2. **監控驗證**：
   - 確認錯誤率恢復正常
   - 確認效能指標恢復正常
3. **問題排查**：
   - 分析錯誤日誌，定位問題根因
   - 修復問題後重新部署

### 回滾影響
- 使用者將無法使用語法高亮功能，回退到純文字顯示
- 不影響檔案下載和其他核心功能

# SkillHub 內建優質 Skills 建設計劃

> 目標：為 SkillHub 預設內建 30～50 個優質 Skill，讓開發者部署完成後立即有一批覆蓋工作與生活的實用內容可以發現、安裝和使用。

## 1. 要做什麼

SkillHub 已經支援透過 manifest 將遠端 Skill 包同步到 `@global`。這項工作不再建設新的分發
系統，而是直接利用現有能力補充內容：

1. 收集一批成熟、實用的 Skill。
2. 完成協議、許可證、安全和可用性檢查。
3. 將審查後原始碼、來源和迴歸用例納入開源倉庫。
4. 確定性打包並上傳官方雲端儲存。
5. 將不可變 URL 和製品 SHA-256 加入
   `server/skillhub-app/src/main/resources/builtin-skills/manifest.json`。
6. 隨 SkillHub 預設部署同步到 `@global`。

目標總量為 30～50 個。當前已有的 `skillhub-hello` 和 `agentguard` 也需要重新檢查，透過質量
標準後才計入目標數量。

這裡的“開箱即用”是指 Skill 在部署完成後已經存在於 SkillHub 註冊中心，使用者可以直接檢視和
安裝；不會自動安裝到使用者的 Agent，也不會自動執行。

## 2. Skill 組合

部署 SkillHub 的人通常是開發者或平臺管理員，但內建 Skill 的使用者和使用場景不應侷限於研發。
內容組合應同時覆蓋日常生活、辦公協作、學習研究、旅行活動和專業工作，讓新例項具備通用價值。
最終數量不必嚴格平均，但要避免全部集中在同一類。

| 類別 | 建議數量 | 示例方向 |
|---|---:|---|
| 日常生活與個人效率 | 5～7 | 菜譜與購物清單、日程整理、家庭活動、習慣計劃、個人事項清單 |
| 辦公與團隊協作 | 6～8 | 郵件、會議紀要、工作彙報、專案計劃、表格、簡報 |
| 內容寫作與創作 | 4～7 | 文章、社交媒體、文案、改寫、翻譯、創意策劃 |
| 學習與研究 | 4～7 | 學習計劃、資料總結、論文閱讀、資訊核查、語言練習 |
| 旅行與活動 | 3～6 | 行程規劃、打包清單、目的地調研、聚會與活動策劃 |
| 開發與 IT | 5～8 | 程式碼審查、測試、除錯、Git、CI/CD、Skill 與 Agent 開發 |
| 資料與業務分析 | 3～7 | CSV 分析、指標解讀、市場研究、使用者訪談、報告整理 |

建議先完成 30 個，確保主要類別都有代表內容；有足夠優質候選時再擴充到 50 個。不要為了湊數
收錄重複、低質量或只有一句提示詞的 Skill。

## 3. 選品來源

按以下優先順序獲取候選：

1. 已經在真實工作或生活場景中使用過的內部或社群 Skill。
2. 有清晰開源許可證、維護記錄和實際使用者的公開 Skill，優先從 Awesome Copilot、
   OpenClaw、Anthropic、Education Agent Skills 和 Mercury 等可追溯上游倉庫逐項篩選。
3. 針對缺失的高頻場景，由 SkillHub 團隊整理或開發。

使用第三方 Skill 時必須保留原作者、來源連結和許可證，不將第三方內容偽裝成 SkillHub 原創。
不接受付費預裝、廣告 Skill 或只有產品宣傳作用的內容。

可以先建立 60～80 個候選池，再從中篩選 30～50 個正式內建。候選數量不是目標，最終質量才是。
聚合站和安裝量只用於發現候選，不能替代上游許可證、安全性和真實效果核驗。

已完成的首輪來源調研和候選分組記錄在
[內建 Skills 候選池](./22-builtin-skills-candidate-pool.md)。後續可以繼續從 OpenAI Skills
Catalog 按單個 Skill 的許可證篩選。Anthropic 的 `docx`、`pdf`、`pptx`、`xlsx` 不允許
再分發；這類內容不進入內建清單。

## 4. 單個 Skill 的入選標準

每個內建 Skill 必須滿足：

- 解決一個清楚、常見的工作或生活任務。
- `SKILL.md`、指令碼、參考資料和資原始檔完整。
- 提供用途說明、呼叫示例、依賴條件和已知限制。
- 至少使用一個真實任務驗證，能夠得到可接受結果。
- 可以在宣告支援的 Agent 或客戶端中正常安裝和使用。
- 沒有硬編碼金鑰、隱藏下載、未宣告聯網或危險自動操作。
- 透過包校驗、安全掃描和人工檢查。
- 作者、來源和許可證清楚，可合法再分發。
- 有明確維護人；出現問題時能夠更新、下架或替換。

存在以下情況直接不收錄：

- 複製其他 Skill，但沒有來源或授權。
- 只有寬泛提示詞，沒有穩定流程或專業內容。
- 必須提供高許可權或敏感憑據，但沒有充分必要性。
- 在醫療、法律、投資等高風險場景中給出未經可靠來源支援的確定性結論。
- 未經使用者確認自動下單、付款、預訂、發布內容或傳送訊息。
- 依賴已經失效的工具、連結或服務。
- 無法透過真實任務復現。
- 長期無人維護，且 SkillHub 團隊也不準備接管。

## 5. 上架流程

每個 Skill 按同一流程處理：

```text
加入候選池
    -> 檢查來源和許可證
    -> 檢查包結構與檔案
    -> 執行真實任務測試
    -> 完成安全掃描和人工審查
    -> 將審查後原始碼和迴歸用例納入倉庫
    -> 打包並上傳官方雲端儲存
    -> 更新 manifest
    -> 在乾淨例項驗證同步、下載和安裝
    -> 合入正式發行版
```

當前內建同步會在 Skill 已發布後再觸發安全掃描，因此加入 manifest 之前的安全檢查不能省略。

所有已發布包必須使用不可變 URL。同一版本不得覆蓋內容；內容有變化時必須發布新版本。

## 6. 推進節奏

### 第一批：15 個

- 優先選擇依賴少、風險低、容易驗證的 Skill。
- 跑通批次檢查、打包、上傳和 manifest 更新流程。
- 已從 70 個候選中選定 A05、A07–A15、B06、B07、B10、B11、B24，共 15 個。
- 15 個候選均已完成必要適配、來源與許可證登記、生產包校驗和靜態安全複測。
- 已完成不可變製品上傳和 manifest 雜湊登記，待完成乾淨例項同步驗證。
- 不要求第一批為了形式上覆蓋全部類別而降低門檻；旅行規劃等缺少合格候選的場景留到第二批。

### 第二批：擴充到 30 個

- 補齊辦公、寫作、學習、旅行、資料分析和專業工作場景。
- 對旅行和日常生活等公開候選較弱的場景，適配合適上游或由 SkillHub 維護少量原創 Skill。
- 清理第一批中實際效果不佳或維護困難的 Skill。
- 30 個全部透過乾淨環境安裝和呼叫檢查後，作為首個正式目標發布。

### 第三批：擴充到 40～50 個

- 根據候選質量補充更專業的場景。
- 只增加與現有內容有明顯差異的 Skill。
- 如果沒有足夠優秀的候選，停在 30～40 個，不為達到 50 個降低標準。

## 7. 驗收標準

完成標準很簡單：

- 預設 manifest 中有 30～50 個透過稽核的內建 Skill。
- 新部署例項能夠將它們同步到 `@global` 並正常展示。
- 每個 Skill 都能下載、安裝，並完成檔案中的至少一個示例任務。
- 每個 Skill 都有明確來源、許可證和維護人。
- 沒有未處理的高危安全問題。
- 七個主要類別都有可用內容，沒有大量重複 Skill。

內建數量可以作為本項內容建設工作的交付指標，但不能用來掩蓋不可安裝、不可使用或無人維護的
問題。若質量只能支撐 30 個，就以 30 個高質量 Skill 交付，不追求表面上的 50 個。

## 8. 後續維護

- 定期檢查下載連結、依賴和示例是否仍然有效。
- 修復內容時發布新版本，不覆蓋舊包。
- 嚴重安全問題立即從後續 manifest 中移除，並對已部署版本執行治理。
- 長期失效或無人維護的 Skill 用更好的候選替換。
- 新增 Skill 繼續遵循同一質量標準，不無限擴大預設內建清單。

## 9. 這次不做什麼

- 不建設新的 Skill 市場或推薦系統。
- 不做 Sponsored Skill、付費預裝或廣告位。
- 不新增複雜的試點、遙測、灰度或運營平臺。
- 不自動把 Skill 安裝到使用者裝置或 Agent。
- 不為了數量批次生成、複製或搬運低質量 Skill。

本項工作的重點就是：選出 30～50 個真正有用的 Skill，檢查好、維護好，並透過現有內建機制
隨 SkillHub 預設提供。
